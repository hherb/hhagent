**MERGED as [#572](https://github.com/hherb/kastellan/pull/572) (`fbe91c4d`) — `mail.get_attachment_text` can now be addressed by `{message_id, filename}`, because the sha256 it used to require is a parameter this planner cannot reliably supply.** Live failure, task 160 (2026-08-17, audit ids 2929–2948): the user asked for the GST proportion of a flight; the planner found message 37413, called `mail.get_attachment_text` with a sha256 that **exists nowhere in the archive**, got localmail's `404 no extracted text for attachment <hash>`, and told the user that extraction of the E-ticket had failed. Extraction health archive-wide is 6879/7006 blobs, 127 failed.

**The hash was in the prompt and the model still got it wrong, which is what makes this a schema defect rather than a model complaint.** Reconstructing the 4 KiB head `extract_scannable_text` built from that 66 KB `get_message` response puts the correct sha256 **6th, at ≈ byte 120** — but keys are discarded, so it arrives as an unlabelled 64-char hex blob the model must identify by shape and then transcribe exactly. A `message_id` + `filename` is short, self-describing, and checkable. New pure module `workers/mail/src/attach.rs` owns the decision (`choose` / `pick` / `missing_text_advice` / `missing_blob_advice`); `handler::resolve_attachment` spends one extra GET to read the hash out of localmail's own response.

**Two smaller defects from the same trace, both fixed here.** (1) localmail returns the *same* 404 for "blob unknown" and "no extracted text yet", and forwarding its sentence verbatim is precisely what convinced the agent extraction was broken — the 404 now carries a repair whose arm depends on **where the hash came from**, since a hash this worker resolved is right by construction and sending the planner to re-copy it would be #536's misdirected-advice defect again. (2) The planner's first attempt used the unqualified method `get_attachment_text` and burned a whole iteration on `-32601` — **fixed later in the same branch by `beeb6bf1`**, described below; this paragraph is written from the trace, before that commit existed.

**Filename matching is a ladder — exact, case-insensitive, then *unique* case-insensitive substring** — so `e-ticket-DQXK68.pdf` finds `Download 470989752-e-ticket-DQXK68.pdf`. Ambiguity is refused with only the *matching* candidates listed, never guessed. **The tier order is NOT load-bearing and the code now says so**: a mutation reordering the tiers survived, and the reason is a proof, not an oversight — a stricter tier's unique match is always in every looser tier, so whenever the strict tier holds one name that name is the loose tier's match too. The doc comment had claimed the order was load-bearing; that claim was prose asserting what the code does not do, the family this file keeps recording.

**Ten mutations, all killed** — including the two 404 arms independently, "ignore the filename", "swallow a bad optional `message_id` into `None`", and "stop reserving room for the planner clamp". Two survived first and both were **test** defects worth naming: the handler fixture served **one** attachment, so `filename` was decorative and a worker that never read it would have passed; and the ambiguity list was pinned against a message whose attachments were *all* candidates, so listing everything looked identical to listing the matches. Both fixtures now have a third element that makes the wrong behaviour observable. Every planner-facing string is bounded by a budget **derived** from `STEP_ERR_DETAIL_MAX` rather than arithmetic in a comment, so lengthening the prose fails a test instead of silently clipping the advice.

**The live re-run then found the SECOND defect, and it is the one that had been doing the visible damage.** Deployed, task 162 used `{message_id, filename}` **on its first attempt and without even fetching the message** — the filename came straight out of the `mail.search` hit, which is the addressing fix working better than designed. Every call still failed: `-32601 unknown method get_attachment_text`. The planner drops the `mail.` prefix, did so four times across tasks 160 and 162, and burned the whole six-iteration budget on it. So `beeb6bf1` completes an omitted namespace at dispatch when the bare name matches exactly one of that tool's advertised methods (`scheduler::tool_dispatch::method_qualify`), resolved against the same `tool_docs()` the prompt is rendered from. It is namespace completion, not spell-checking: a method that already names a namespace is never rewritten, an exactly-advertised method wins over any suffix match, and an ambiguous bare name is left for the worker to refuse. **After it, the task takes two steps** — `mail.search` → `get_attachment_text{message_id, filename}` (auto-qualified) → answer.

**Six more mutations, all killed, and again the two that survived first were the guards that mattered.** Neither `advertised.contains` nor `contains('.')` was pinned, because both fixtures were too small to expose them: with `["run"]` a dropped exact-match check changes nothing, but with `["run", "a.run"]` it rewrites an exactly-correct method into a *different* one. Third session in a row that a mutation run, not a review, found the fixture too small to fail.

**The Mac bring-up surfaced two things worth keeping.** (1) **launchd bakes `EnvironmentVariables` into the plist at install time, while systemd reads `EnvironmentFile=` at run time** — so on macOS the operator overlay `kastellan.env.local` must exist *before* `install`, or it is silently absent from the running daemon. The installer does say `operator overlay: none at …`, which is the line to read. (2) **A force-routed loopback origin needs an `IPAddress` SAN, not a `DNSName` holding an IP literal.** The endpoint must be an IP literal (force-routing SSRF-blocks local *names*; a literal goes through the proxy's carve-out), and rustls then matches only an IP SAN. The Mac's localmail cert carried `DNS:127.0.0.1, DNS:localhost` and every dispatch died at `mitm_failed: origin TLS handshake … certificate not valid for name "127.0.0.1"`. The DGX had worked only because its cert happens to carry `IP Address:10.0.0.3, IP Address:127.0.0.1`. localmail's own `serve/tls.py` documents the trap and `rotate-tls` emits IP SANs correctly — the Mac cert simply predated it. **This also discharges the ROADMAP's standing "macOS Seatbelt-loopback verification of tier 1a" deferral: the Seatbelt profile was never the problem** (`(deny network-outbound)` + a UDS `path-literal` allow behaved exactly as written), and the mail worker's macOS force-routed loopback path is now exercised end to end against a real 127k-message archive.

### The multi-agent review round (2026-08-17) — what it found, and why the mutation count was misleading

A five-agent review of the whole branch (general, silent-failure, test-coverage, comment-accuracy, type-design) landed **nine findings worth fixing**, all now fixed on the branch. Two are worth carrying forward as lessons rather than as changelog:

**"21 mutations killed" measured the author's chosen mutations, not coverage.** The reviewer ran **15 mutations of its own against `workers/mail` and 11 survived**, all 113 tests green under each. They clustered exactly where the per-module rounds had not looked: the *shared* guards (`is_sha256`'s length clause was droppable — `is_sha256("")` is vacuously `true`, which builds `/v1/attachments//text`), the new-but-untested `ids::id_strings` (its empty-list guard could be deleted, sending localmail a filter matching nothing), and `with_candidates`' budget arithmetic. A mutation score is only as good as the mutation set, and a per-module set systematically misses the code two modules share.

**The clamp property test asserted an upper bound and no lower bound, which inverted its own purpose.** `with_candidates` *breaks* rather than truncates, so raising `NAME_HEAD` makes a message **shorter** — every name stops fitting and the planner gets prose plus `…` with nothing to choose from. `NAME_HEAD` 44 → 400 survived, listing zero candidates, while the "no message grows past the clamp" assertion passed throughout. That is precisely the silent clipping the derived budget exists to prevent. There is now a companion test asserting at least one candidate survives, plus a boundary sweep over every name length up to `NAME_HEAD`.

**The substantive defects, all of the same family this branch was opened for — advice the planner cannot act on:**

- **A message whose attachments share a filename was a guaranteed loop.** `image001.png` twice → *"copy one exactly: image001.png, image001.png"*. The planner copies the name it was given, gets a byte-identical error, and repeats to the iteration cap. Refusals now list whichever key actually discriminates (`attach::how_to_name`): filenames when they are distinct and non-empty, **12-char sha prefixes** otherwise — and `pick` accepts a unique prefix, so the advice terminates. Nameless attachments used to render as an empty list entry (`… exactly one of: , real.pdf`) and were unaddressable; they are now listed by sha.
- **Three upstream states shared one sentence, and it was false in two of them.** A message with genuinely no attachments was told to *"re-check the mail.get_message output for one with a sha256"* — output that visibly has none. An entry with `"sha256": null` (localmail really emits this) was dropped silently, so naming it got *"No attachment in message X has that filename"* about a filename the message plainly has. Each state now gets its own true statement.
- **`mail.get_attachment` never got the 404 treatment its sibling got** — it still forwarded localmail's bare `404: attachment <sha> not found`, the exact ambiguous sentence this branch was opened to eliminate. Worse, `missing_text_advice`'s resolved arm *routes the planner there* ("use mail.get_attachment instead"), so it was the second step of an advice chain that dead-ended. New `missing_blob_advice`, same planner-supplied/resolved split.
- **The message-detail 404 was forwarded raw.** localmail deliberately returns the same 404 for "no such message" and "your ACL excludes it" (permission state must not be enumerable), so the agent would tell the user the mail does not exist. Now a repair naming both causes.
- **A `sha256` and a `filename` naming *different* attachments were resolved by silent precedence.** For `mail.get_attachment` that wrote the *other* document to disk, under a name matching it, and reported success — while `search_params::normalize_filters`, one file over, refuses the analogous doubled id filter and cites `attach::choose` as its precedent. The message is already fetched, so the check is free; divergence is now refused.

**Two structural fixes:**

- **`Picked` had an inverted encapsulation**: private constructor, `pub` fields — so `handler`, a sibling module that cannot see a private `fn new`, had *no way* to build one except by struct literal. The design forced every external caller to bypass validation. Fields are private now and `Picked::from_planner_sha` is a fallible constructor, which also absorbed `handler::validate_sha256`. This is the `LocalmailId` rule applied to the other URL segment.
- **Namespace completion is applied to the plan, not only at dispatch.** `qualified_method` ran inside `dispatch_step` and assigned to a local, so `plan.steps[i].method` kept the bare name — and `summary::ok_summary_cap` keys the per-step output cap on exactly that field. A step written as bare `search_batch` therefore newly *succeeded* (it used to fail `-32601`) while its result head was capped at the flat 4 KiB instead of the batch-scaled 24 KiB: **a silent 6× cut in what the planner reasons from, on a path this feature created.** `inner_loop::qualify_plan_methods` now normalises `plan.steps` once, after invoke expansion and before review, so CASSANDRA, the plan digest, the output cap and both audit payloads all see the method that goes on the wire. `plan.formulate` is written earlier, so the planner's own wording is still on the record. The dispatcher's chokepoint check stays (idempotent) because that, not the loop, is what every dispatch path passes through.

**The line joining the two halves of the namespace fix had no test at all.** `method_qualify`'s 8 unit tests passed literal arrays; `registry_build`'s test checked `methods_for` in isolation; nothing exercised the dispatcher calling `methods_for(&step.tool)` and passing the result to `dispatch`. Reverting that one line left the entire workspace suite green while restoring the live failure. The stated reason for the gap was wrong and is now corrected in place: the comment in `tool_dispatch/tests.rs` claimed the dispatcher "needs a real `PgPool` to construct, so a pure unit test would be tautological", but `connect_lazy` parses a URL without connecting — which is how `core/tests/handoff_dispatch_e2e.rs` has built it hermetically all along. **A belief about what cannot be tested is worth checking before it is written down as a reason not to.**

Also fixed: `id_strings` took a stringly-typed key and carried an unreachable "not an id filter" arm whose message blamed the planner for a worker-side typo — it takes `IdField` now and returns validated `LocalmailId`s; an explicit `null` id filter is absence (matching `opt_message_id`) rather than a shape error; `with_out_dir` cleans up from `Drop`, so a failing assertion no longer leaks `KASTELLAN_WORKER_OUT` into whatever runs next.

**Prior on this branch's base — `feat/564-slice-1a-ask-record` MERGED as [#570](https://github.com/hherb/kastellan/pull/570) (`06c65ae7`) — [#564](https://github.com/hherb/kastellan/issues/564) slice 1a, the durable ask record. DB layer only; the hot path is untouched.** `Verdict::Escalate` — CASSANDRA's one verdict for *"a human must decide"* — still degrades to `Block`, because `channel/bus.rs` is strictly inbound-task → outbound-reply and core cannot initiate a question and suspend a task on the answer. This slice builds the record that primitive rests on: migration 0023 (`asks` + `tasks.state='awaiting_operator'` + a dedicated `tasks_resumed` NOTIFY channel), `db::asks` (`raise`/`resolve`/`expire_due`/`cancel_for_task`/`get`/`list_pending`), four executor-generic `db::tasks` helpers + a widened `mark_cancelled`, and the pure `core::cassandra::plan_digest`. Spec + plan: [`2026-08-16-ask-record-slice-1a-design.md`](../../superpowers/specs/2026-08-16-ask-record-slice-1a-design.md).

**Where the slice STOPS is the load-bearing decision.** `Outcome::AwaitingOperator`, `drain_lane`'s non-finalize branch, and the `Escalate` wiring are all slice 1b — **excluded together and for one reason**: `drain_lane`'s suspend branch is reachable only from the `Escalate` arm, so shipping the plumbing without its producer ships a branch no test can reach. That is the "a check that cannot fail" family this repo keeps paying for (#539's `Err`-arm assertions, #542's shared-prefix probe, the four fail-open defects in the Shieldstral harness). The issue's own slicing put them apart; this is a deliberate deviation from it.

**An approval binds to a plan DIGEST, and the resumed task is re-reviewed.** `run_one` rebuilds `TaskContext` from the payload with `plan_count: 0`, so a resumed task **replans from scratch** and the escalated plan is gone. Binding to nothing lets approving plan P run plan P′ unreviewed; binding to the plan itself needs a review-bypass carve-out in the one place the architecture has none. So the ask stores a digest, the resumed plan goes through CASSANDRA again, and a matching digest lets the `Escalate` arm consult the resolved ask instead of raising a second one.

**The digest is an EXCLUSION list, and that shape is the point.** Drop exactly four narration fields (`context`, `rationale`, per-step `returns`/`done_when`); count the other ten. An inclusion list makes *forgetting* the failure mode, and forgetting fails unsafely — an approval carrying to a plan differing in the forgotten field. **It had already bitten: the first draft named 7 included fields and `Plan` has 12**, silently dropping `floor_request` (which feeds `apply_floor_raise`, so it changes the floor the whole plan is reviewed against). `canonical_form` destructures `Plan` and `PlannedStep` with **no `..`**, so a 13th field is a compile error, not a silent exclusion — that is what caught it. Also counted, and not merely swept in: `invoke_skill` drives L3 expansion, `l3_skill`/`python_skill` crystallise persistent reusable artifacts (the latter carries `code`), `l1_insight` is written to memory. **Provisional** — the revisit trigger is the first real escalation that re-escalates on a semantically identical replan.

**Two deviations from the issue, both argued in the spec.** Expiry moved *into* this slice (it is pure PG, and suspension without it adds a way to wedge a task permanently — the headless-daemon failure the issue itself names). And cancelling a task cancels its pending asks **inside `mark_cancelled`'s own transaction**, coupling `db::tasks` to `db::asks` deliberately: with a separate cancel-both helper, any caller reaching for plain `mark_cancelled` — the CLI cancel path is one — silently strands the ask. Same argument `AllowlistDecl` made in #545.

(2) `resolve`'s exactly-once assertion was never evaluated under its own mutation — the panic landed a layer earlier — and its comment claimed an overwrite that the transaction makes structurally impossible. (3) `expire_due` swept exactly one ask, so a loop that stopped after the first row passed. (4) "a cancelled ask is not expiry's business" returned empty because the **deadline had not passed**, not because the ask was cancelled — revert `cancel_for_task` entirely and it still passed. All four are the #539 shape in new costumes. **And a mutation that killed a test also disproved a second assertion:** dropping `lease_expires_at = NULL` from `suspend_for_ask` fails at `lease_expires_at.is_none()` but **not** at the adjacent `!any_live_worker(...)`, which could not have caught it — the mutation leaves `state = 'awaiting_operator'` and that helper filters on `'running'`. One of those two assertions was load-bearing for the lease property; the other never was.

**The whole-branch review found four Important defects that no per-task review could have, and the pattern is worth naming: each per-task review was scoped to its own brief, so nothing was looking at the helpers as one state machine.** (1) **`resolve` was keyed by row id, not nonce, so D3's unforgeability property was unreachable through the API** — the model D3 cites (`pairings::claim_code`) deliberately has *no* by-id form, and a slice-2 Matrix handler parsing `resolve 41 approve` would let any peer in the room approve any escalated plan by guessing a small integer. `resolve_with_nonce` now guards on `nonce_sha256`, with the shared body factored so the two resolvers cannot drift. (2) **A lock-order inversion**: `mark_cancelled` locked tasks→asks while `resolve`/`expire_due` lock asks→tasks, so a concurrent cancel + approve deadlocks (SQLSTATE 40P01) and `expire_due` holds every due ask for its whole sweep. Fixed by moving the ask-cancel above the tasks UPDATE. (3) **`RaisedAsk` derived `Debug` over the plaintext nonce**, one screen below the comment explaining `Ask` deliberately has none. (4) The four desync-capable helpers were `pub`; `suspend_for_ask` called from outside `raise` wedges a task in `awaiting_operator` with **no ask**, which `claim_one`, `sweep_crashed` and `expire_due` all skip. 1. **The lock reorder traded a deadlock for a stranded ask, and both halves were MEASURED against a live PG 18 rather than argued.** Round 1 moved `mark_cancelled` to asks→tasks to kill a real `resolve`-vs-cancel deadlock (confirmed: SQLSTATE 40P01 under the old order). The strict path parses the whole raw response, so its error always describes the markdown fence: `expected value at line 1 column 1` — i.e. *"your output wasn't JSON."* The model was in fact returning **complete, correct, well-formed fenced plans** that merely omitted a required field; the real error was `missing field 'steps'`. Every reader, human and agent, was pointed at the fence, at empty completions, at context overflow — none of which were happening. **Cost the entire session** until the raw output was finally logged. ### The fail-open `data_ceiling` correction

`data_ceiling` is a **ceiling**, so the most *sensitive* `DataClass` is the most *permissive* value it can hold. #505 defaulted an absent field to `Secret` and shipped it documented as fail-**closed**; `Secret` is rank 3, the maximum. The field has exactly two enforcement points, both in `cassandra/deterministic.rs`: **I1** (`ceiling >= floor`) can never fire at rank 3 whatever the floor, and **I3** (`step.classification <= ceiling`) can never fire because no step class outranks it. A plan omitting the field is therefore **not ceiling-constrained at all** — where it was previously rejected outright.

Severity is bounded and worth stating precisely: I1/I3 only ever catch a model contradicting *its own* declarations (a competence signal, not an attack barrier — a hostile planner would declare a matching high ceiling). **The second review round narrowed the "I2 is still enforced" claim**, which was too broad: an `invoke_skill` plan's steps are *not* model-written — L3 expansion stamps each expanded step's `classification` with `plan.data_ceiling` (`memory::l3_invoke::agent` / `l3py_invoke::agent`) and runs at `inner_loop` step 1b, **before** the reviewer at step 2 — so on a plan that both omits the field and invokes a pinned skill, the expanded steps carry rank 3 and I2 passes vacuously for them too: **all three invariants, not two**. Nothing outside `deterministic.rs` reads `step.classification`, so the effect stays inside that review stage. A defect in a defence-in-depth layer, not a hole in the threat-model boundary. Behavioural fix: [#506](https://github.com/hherb/kastellan/issues/506).

### Egress / MITM traps (from #491–#503) — read before touching the proxy

1. **A `CA:TRUE` self-signed *leaf* is rejected at handshake** with rustls' `CaUsedAsEndEntity`, even though `openssl verify` accepts it — and `openssl req -x509` commonly produces exactly that shape. It fails **late and opaquely** as a `mitm_failed: …` egress decision, not at startup. The live DGX localmail cert WAS this shape; regenerated `CA:FALSE` on 2026-07-26 (backups `~/.config/localmail/tls/*.cabak-20260726-173651`) and the tier then passed. Working shapes: a non-CA leaf (`CA:FALSE`) or a real CA that signed a separate leaf. Verify with `openssl x509 -in <cert.pem> -noout -text | grep -A1 'Basic Constraints'`.
2. **The upstream anchor is trusted for EVERY host that sidecar can reach**, not just the keyed origin. #492 therefore *enforces* single-private-origin rather than trusting operator discipline: an anchor is handed out only when the worker's allowlist resolves to a single private origin written as an **IP literal** (privateness via `kastellan-net-classify::is_denied_range`, the proxy's own SSRF predicate, so the two can't drift), and **a refusal fails the spawn**. **Known limitation, documented and test-pinned, not closed:** keying is per-**host**, not per-service, so two private services sharing one address (the DGX's actual shape: localmail `:8443` + SearxNG `:8888` on `10.0.0.3`) are one origin to the rule and the second worker's sidecar also receives the first's anchor. Closing it needs `host:port` keying or a per-host rustls verifier (#492's explicit non-goal); mitigation is operational — give co-located private services distinct addresses.
3. **`tls_intercepted: true` is weaker than it reads** — emitted when the proxy takes the MITM branch, *before* the upstream handshake. **Round-tripped bytes are the load-bearing assertion.**
4. **The decision-ingest thread is deliberately DETACHED**, so reading captured rows right after `worker.close()` races its drain — worst for a connection's LAST decision. Any test asserting on a *terminal* egress decision must poll to quiescence (the shared helper does).
5. **UDS path length:** a merely descriptive scratch-dir prefix under macOS `$TMPDIR` pushes `<scratch>/egress.sock` past `sun_path` (`SUN_LEN` error) and the sidecar dies before reading the CA. Use `tests-common::short_scratch_root`.
6. **The proxy's upstream leg trusts webpki roots ONLY** unless the operator sets an anchor — so **no hermetic self-signed origin is possible for a MITM'd worker's e2e**; real-origin tiers are structural, not lazy ([[egress-proxy-upstream-trusts-webpki-only]]).
7. **Egress-decision assertions must match `host:port`, not a bare host** — a bare-host check passes on any decision mentioning it, and on the DGX loopback SearxNG and the embed endpoint share an address (cost a #448 round-trip; the convention is `is_allowed_row_for` / `is_for_origin`).

### Process lessons that have each cost a re-run

- **Write long-run logs to `$HOME`, never `/tmp` — on BOTH hosts.** `/tmp` is scrubbed mid-run on the DGX *and* on the Mac; macOS deleted a completed `cargo test --workspace` log plus the harness task-output files, forcing a second 45-minute gate. Include an explicit exit-code line and a DONE sentinel. [[dgx-run-logs-tmp-scrubbed]]
- **Each host is structurally blind to the other's `cfg` arms.** Mac clippy compiles `#[cfg(target_os="linux")]` items out, so an unused cfg-linux helper passes on the Mac and fails the DGX `-D dead-code` gate; the mirror direction is real too (the DGX is blind to DE-gated items in dual-platform files). Gate both hosts after scripted edits. [[cfg-linux-e2e-deadcode-dgx-clippy]]
- **Don't race sidecar tests against a build.** The 5 s sidecar-readiness budget is load-sensitive: `email_mitm_e2e` took 28.6 s loaded vs 8.2 s quiet, and `egress_force_routing_e2e::forced_coupling_…` fails under full-workspace load but passes 3/3 standalone in ~0.11 s. **Don't "fix" it by inflating a production timeout.** Adjacent: [#328](https://github.com/hherb/kastellan/issues/328). (The *leaked* sidecar children were a different thing — #502, fixed in PR #516.)
- **Mac CLI cargo blocks on the IDE's rust-analyzer** holding `target/debug/.cargo-lock` — use a scratch `CARGO_TARGET_DIR` (e.g. `$HOME/.cache/kastellan-sdd-target`) or iterate on the DGX. Never pipe background cargo through `| tail` (masks the exit code, buffers output). [[mac-cargo-buildlock-prefer-dgx]]
- **Verify deployment claims before carrying them forward** — issue comments and handovers go stale; check the live host before repeating a claim in a spec, PR or ROADMAP. [[handover-claims-verify-before-carrying]]

**Both hosts are load-bearing, in opposite directions — always check both.** The two supervisor backends compile on one host each: a `launchd_agents.rs` change is invisible to the DGX and a `systemd_user.rs` change is invisible to the Mac, so the two hosts legitimately report different counts. **Predict the count, then reconcile the delta exactly.** Every gate in the table above was predicted from the diff's new `#[test]` count and investigated when it missed. That is the cheapest available detector for "a test I think I added is not being compiled" — which is precisely the failure the platform split produces.

**Mac verification runs under a private `CARGO_TARGET_DIR`** (the IDE's rust-analyzer holds `target/debug/.cargo-lock` — [[mac-cargo-buildlock-prefer-dgx]]), and **it must live under `$HOME`, not `/tmp`**: macOS scrubbed a scratchpad target dir *mid-run* once, so a test binary vanished between build and exec (`TEST_EXIT=101`) while every `test result:` line still said `ok`. Same `/tmp` hazard as the run logs, one layer down — [[dgx-run-logs-tmp-scrubbed]]. And skip-as-pass counts as passed, so counts stay comparable with or without `--nocapture`.

#### What CI does not cover

`linux-check.yml` is **compile-only** — `cargo check --workspace --all-targets`, `clippy -D warnings`, and `cargo test -p kastellan-tests-common` (hermetic structural guards only). The workflow header argues that scope deliberately, and it is the right default. But it means a green PR check says *nothing* about behaviour, and two consequences are worth holding in mind rather than rediscovering:

- **`cargo test -p kastellan-supervisor` never runs on a PR.** So #508's regression guard — the tests pinning that `install`/`install_target` actually call `systemctl --user enable` — is enforced only by an operator running the DGX suite. Both tests are `cfg(target_os = "linux")` *and* `[SKIP]` without a live user manager, which `ubuntu-latest` does not have, so simply adding the job would not fix it. [#510](https://github.com/hherb/kastellan/issues/510) tracks the options (a `REQUIRE_USER_MANAGER=1` knob first, then a runner that can satisfy it).
- **There is no macOS job at all** — `.github/workflows/` is `linux-check.yml`, `docs.yml`, `release.yml`. So for `cfg(target_os = "macos")` code the gap is not "never run", it is **never compiled**: the launchd backend, its tests, and every macOS arm of a dual-platform file are invisible to CI, and the Mac is the only host that sees them (the mirror of [[cfg-linux-e2e-deadcode-dgx-clippy]]). That is the concrete reason #511 folded the two backends' staging helpers into one `cfg`-free module: shared code gets compiled and tested on a PR, per-backend code does not.
- **The one lever that does work: `tests-common`.** Its unit tests *are* run on every PR, which makes it the right home for hermetic *structural* guards over things CI otherwise cannot see — the provisioning sha256 pins, and since #504 the installer-coverage guard (`installable.rs`) that fails when any binary the workspace builds is neither installed nor explicitly exempted. If a defect's character is "survives every check not specifically looking for it", that crate is where the check belongs.
- More generally, **any invariant whose only guard is an integration test is DGX-gated**, and integration tests that skip-as-pass are indistinguishable from tests that ran. The #508 arc is the worked example of why that matters: correct-looking code, green everything, broken only after a reboot nobody performs during development.

**Standing macOS test-infra gotcha (not a regression):** a *full-workspace* run under `KASTELLAN_PG_BIN_DIR` flakes ~4 tests in `core/tests/embedding_recall_e2e.rs` at PG bring-up (`tests-common/src/pg.rs`) — parallel `initdb`/launchd churn (issue [#130](https://github.com/hherb/kastellan/issues/130) territory); they pass single-threaded and in isolation. Use skip-as-pass for the whole workspace on the Mac and run live-PG suites individually or on the DGX. Two `error[E…]` blocks in a full log are the **expected output of two pre-existing `compile_fail` doctests** (`Lifecycle::IdleTimeout` non-exhaustive, `WorkerCommand::new` private), both reporting `... ok` — not failures.

**Core & shared libraries**

- **`core`** (`kastellan-core`) — lib + 2 bins (`kastellan` daemon, `kastellan-cli`). Pure builders (initdb/auto_conf/bin-dir), `probe::run`, runtime-role separation, `audit`, `memories` (three lanes + `truncate_to_embedding_dim`, **EMBEDDING_DIM = 256**, Matryoshka), `graph`, `tool_allowlists` (argv0 vs domain kinds), `pairings`, `secrets` (AES-256-GCM + OS keyring). **`sqlx::migrate!` embeds at COMPILE time** — `touch db/src/lib.rs` after adding a migration ([[sqlx-migrate-embeds-at-compile-time]]).

Honouring it on one OS only is a parity break. The contract stops at *arming* the unit: getting a per-user manager up on a host nobody logs into is the host's job on **both** platforms (linger on Linux, a GUI session on macOS), so "survives a reboot" is this contract plus a host-level arrangement. ## Key design decisions locked in

- **Vendor-neutral, AGPL-compatible deps only.** Apache-2.0 / MIT / BSD / MPL / LGPL / (A)GPL fine; CDDL, BUSL, SSPL, Elastic and "source-available" are blocked.
- **Cross-platform first-class.** Linux (DGX Spark primary) + macOS. No Linux-only code without a macOS counterpart of equivalent guarantee.
- **Rust core, Python only inside sandboxed workers.** No PyO3, no in-process Python; the core never executes untrusted code in-process.
- **One process per worker, one OS sandbox per worker.** No "spawn unsandboxed" escape hatch in `tool_host` — don't add one.
- **Hybrid LLM with policy routing.** Local-first over OpenAI-compatible HTTP; Frontier only via the Phase-5 policy gate, through the egress proxy.
- **Single-host deployment via OS-native user-level supervisors** (`systemd --user` / launchd). No k3s.
- **Fixed core tools, sandbox-bound agent-authored Python.** Named/persisted skills get a human-approve gate (the L3 arc).
- **JSON-RPC 2.0 over stdio** — MCP-stdio compatible, so a richer MCP client can be swapped in without moving the trust boundary.
- **The operator→daemon command channel is the Postgres `tasks` queue + `LISTEN/NOTIFY`**, not a new IPC socket. `ask` and `memory l3 run` both ride it (#179 Opt-3).
- **Threat-model invariant:** worst-case compromise reaches *at most* the agent's own OS user, its own Postgres role, its own scratch FS, and the allowlisted endpoints for the *one* compromised tool. Nothing else.

## Inspirations / things to read before each milestone

Two adjacent OpenClaw-derived projects ship AGPL-compatible code worth reading before a new milestone:

- **ZeroClaw** ([`zeroclaw-labs/zeroclaw`](https://github.com/zeroclaw-labs/zeroclaw), 100 % Rust) — [`crates/zeroclaw-runtime/src/security/`](https://github.com/zeroclaw-labs/zeroclaw/tree/main/crates/zeroclaw-runtime/src/security) has working `bubblewrap.rs`, `landlock.rs`, `seatbelt.rs`, `pairing.rs`, `webauthn.rs`, `leak_detector.rs`. **Don't copy its in-process tool model** — tools run as in-process Rust traits with the OS sandbox around the whole runtime, a weaker boundary than process-per-worker.
- **IronClaw** ([`nearai/ironclaw`](https://github.com/nearai/ironclaw)) — read its dispatcher chokepoint pattern (`ToolDispatcher::dispatch()` as the single audit/safety funnel for every action). Drawbacks: WASM-as-boundary is software-only containment; the Postgres+libSQL dual backend is overkill at our stage.

The *defining* architectural difference: kastellan enforces **one OS process + one bwrap/Seatbelt jail per worker**. Both reference projects retreated from that. Don't.

**openworker** ([`andrewyng/openworker`](https://github.com/andrewyng/openworker), MIT — Python sidecar + Tauri shell) and its engine **aisuite** ([`andrewyng/aisuite`](https://github.com/andrewyng/aisuite)), surveyed 2026-08-14. **Read it for consent ergonomics, never for containment** — it has no OS sandbox at all (`coworker/tools/shell.py` runs on the host; isolation is path-scoping plus an in-process permission engine), so its threat model is strictly weaker than ours and taking its security architecture would be a regression. What it *has* done far more work on than kastellan is everything around an agent that runs while nobody is watching, which is our default posture and its edge case. Five modules earned ROADMAP entries — the ask channel (`coworker/inbox.py`, [#564](https://github.com/hherb/kastellan/issues/564), Phase 3), declared tool risk + operator-local overrides (`risk.py`/`overrides.py`, Phase 5), target-bound standing grants (`permissions.py`, Phase 5), auto-compaction (`compaction.py`, Phase 1 `context_manager`), and `SKILL.md` progressive disclosure (`skills/`, Phase 4). Two things they have that we already do **better**, so don't re-import them: aisuite's `artifact_store` message dehydration is a weaker `handoff.rs` (preview + ref, no range-fetch with `eof`), and their careful shell-metacharacter rejection before allowlist matching exists only because `run_shell` takes a command *string* — `shell-exec` takes an argv array and never invokes a shell, so the whole bug class is absent. The one refinement worth noting from that code: we allowlist `argv[0]` only, so `git status` and `git push` are the same permission; their `shlex`-parsed **token-prefix** match (`git status` matches `git status -s`, never `git statusfoo` or a bare `git`) is the right algorithm if sub-command granularity is ever wanted.

## How to update this document at session end

**Header first, prose last.** The header is what the next session treats as authoritative; stale header fields mislead silently even when the prose is right.

1. **Bump the header before writing any prose:** `Last updated:` → today; `main` HEAD → `git log --oneline -1`; `Last gate:` → the passed/failed/ignored/`[SKIP]` counts from a fresh `cargo test --workspace`. Then fix **every test count embedded elsewhere that changed** — a fresh agent greps for them and trusts whatever it finds.
2. **Move the picked TODO into [Recently merged](#recently-merged)** with enough detail (file paths, why-not-X, gotchas, count delta) to start cold, and update the [Test baseline](#test-baseline-authoritative) table.
3. **Write a fresh [Next TODO](#next-todo)** with options sized for one session each — file paths, gotchas, verification step.
4. **Refresh [Working state](#working-state)** — anything new, anything that became real.
5. **Tick the matching ROADMAP items** with the commit hash.
6. **Commit both files together** with a `docs(handover): …` message.
7. **If a milestone shipped:** does `site/roadmap.html` (timeline + "Last updated" stamp, and the landing-page status numbers) need a one-line update? See `site/README.md`.

### Pruning convention

This file stays focused on **what the next session must act on**: current state, the last 2–3 sessions, and the next TODO. Prune when it grows past what a fresh session can absorb cold — judge by *reading weight*, not line count; the 2026-08-03 prune was triggered at 546 lines / ~73 k tokens.

1. **Snapshot first** — copy to `archive/handover_<YYYYMMDD>[_<slug>].md`. The archive is the audit trail: never edited after the fact, never deleted.
2. **Keep:** the header, "Read these first", "Working state" (current truth), the most recent 1–2 sessions, "Key design decisions", "Next TODO", open issues, open questions, "Inspirations", and this section.
3. **Compress everything else** into one bullet per session, or into the archive pointer if it is no longer load-bearing.
4. **Cross-link** every compressed bullet to the archive snapshot.
5. **Commit the prune separately** (`docs(handover): prune older sessions, archive pre-prune snapshot`) so the diff is reviewable.

The archive directory is the historical record; this file is the working brief.
